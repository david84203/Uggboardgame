# 07 · 實作狀態與部署

## 1. 系統化架構（Han 決策 2026-09-15）

原則：**AI 只做分類，規則做決定，模板做文字。**

| 步驟 | 誰做 | 檔案 |
|---|---|---|
| 拍照、EXIF 修正、縮圖 1024、JPEG 0.82 | 客端 | `src/beauty/capture/preprocess.js` |
| 亮度、模糊檢查 | 客端 | `src/beauty/capture/quality.js` |
| 478 點特徵點、臉型幾何（臉長寬比、額顴顎三寬、下顎角、下巴尖銳度）、三庭五眼、偏頭、臉框占比、膚色 Lab | 客端 MediaPipe | `src/beauty/capture/measure.js` |
| 臉型候選與分數（高斯距離） | 規則 | `src/beauty/rules/faceShape.js` |
| 比例特性分類（眼距、中庭、下庭、顴骨、眉眼距） | 規則，不經 AI | `faceShape.js` → `classifyProportions` |
| **五個分類 + 兩句話**（品質、臉型在候選中選、量感、冷暖色調與明度彩度、膚質） | **AI** | `api/beauty/_lib/prompt.js`、`_lib/ai/*.js` |
| 腮紅 / 修容 / 打亮位置 + 比例微調 | 規則 | `src/beauty/rules/placements.js` |
| 腮紅、唇、眼影、服裝色票 | 固定色表 | `src/beauty/rules/palettes.js` |
| 報告文字（措辭依信心度） | 模板 | `src/beauty/rules/copy.js` |
| 商品 2 保養 + 2 彩妝 | 規則 | `api/beauty/_lib/products.js` + `src/beauty/data/products.json` |
| 組裝完整報告、機器標籤 | 規則 | `src/beauty/rules/buildReport.js` |

AI 回傳格式由 `src/beauty/rules/aiOutputSchema.js` 定義，同時用於 Structured Output（伺服端保證）與 Ajv 二次驗證；驗證失敗自動重試一次。

## 2. 程式碼位置

```
src/beauty/
├── BeautyApp.jsx          流程殼（歡迎→指引→拍照→風格→分析→報告）、/beauty/report/:id、/beauty/privacy
├── api.js                 呼叫後端 + 事件批次
├── liff/useLiff.js        獨立 LIFF（VITE_BEAUTY_LIFF_ID）、oaMessage、sendMessages
├── capture/               preprocess / quality / measure（MediaPipe）
├── rules/                 labels / faceShape / placements / palettes / copy / buildReport / aiOutputSchema
├── ui/                    Welcome / Guide / Capture / StylePicker / Analyzing / Privacy / theme
├── report/                ReportPage / FaceDiagram（SVG 圖解）/ flex（Flex Message）
├── share/shareCard.js     1080×1920 限動卡（含 QR）
└── data/products.json     商品對照表（由 docs/beauty-ai-liff/products-template.csv 轉出）
api/beauty/
├── analyze.js             POST：驗證 → 額度 → AI → 規則 → 存檔
├── event.js               POST：事件批次
├── report.js              GET：本人重開報告
└── _lib/                  line（ID Token 驗證）、firestore、validate、prompt、products、http、ai/{claude,gemini,index}
```

路由：`src/main.jsx` 掛 `/beauty/*`（lazy chunk）；`vercel.json` 加了 `/beauty` rewrite；PWA denylist 加了 `/beauty`。桌遊店的 LIFF 在 `/beauty` 下不初始化（一頁只能 `liff.init` 一次）。

## 3. Firestore 集合

| 集合 | 內容 |
|---|---|
| `beauty_users/{lineUserId}` | displayName、pictureUrl、tags[]、daily{日期:次數}、lastAnalysisId |
| `beauty_analyses/{BL-yymmdd-XXXX}` | uid、report（完整報告）、input（無影像）、meta（tags、products、provider、model、usage、耗時、promptVersion） |
| `beauty_events/{auto}` | uid、type、analysisId、payload、ref、ts |
| `beauty_idempotency/{uid_key}` | 防重送 |
| `beauty_config/daily_{日期}` | 全站當日次數 |

客端不直接讀寫這些集合（全走 Admin SDK）；Firestore 規則對 `beauty_*` 保持拒絕即可。

## 4. 部署前要做的設定

1. **LINE Developers**（用 Han 的 Provider）
   - LINE Login channel → 記下 Channel ID → `LINE_LOGIN_CHANNEL_ID`
   - 在該 channel 新增 LIFF App：Size Full、Endpoint `https://<網域>/beauty`、Scope `profile openid`、Bot link `On (Aggressive)` 並綁 `@726rmfol` → LIFF ID → `VITE_BEAUTY_LIFF_ID`
2. **Firebase**：專案設定 → 服務帳戶 → 產生私鑰 → 整份 JSON 壓成單行 → `FIREBASE_SERVICE_ACCOUNT`
3. **Anthropic Console**：建立 API key → `ANTHROPIC_API_KEY`（付費制；每次分析約 NT$1）
4. **Vercel 環境變數**：照 `.env.example` 填；`DEV_BYPASS_TOKEN` 正式環境不要設
5. **六格選單**：其中一格 URI 設 `https://liff.line.me/<LIFF_ID>?ref=menu`
6. **立牌 QR**：`?ref=store_counter`、`?ref=store_makeup`

網域：目前掛在本 repo（uggboardgame.com）。LIFF Endpoint 可以是任何 HTTPS 網址，但建議之後用 Han 自己的網域指到同一個 Vercel 專案，或把 `src/beauty` + `api/beauty` 搬到照相館的站（`sarangheyo-site`）。程式碼是自包含的，搬移成本低。
